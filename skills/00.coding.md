# Skill 00: Architecture & Coding Standards (SHRM Web App)

## 1. Overview & Philosophy
The **SHRM Study Platform** is engineered as a high-performance, zero-dependency, single-page application (SPA). It runs completely client-side without compilation steps, bundlers, or backend servers. It is optimized for instant loading, offline capability, and seamless deployment onto static hosts such as **GitHub Pages**.

### Core Tenets
1. **Zero Runtime Dependencies**: No React, Vue, jQuery, or third-party libraries. All logic is written in clean, modern vanilla JavaScript (ES6+).
2. **Instant Paint & Zero Flash**: CSS theme initialization executes synchronously in `<head>` before rendering to eliminate flash-of-unstyled-content (FOUC).
3. **Decoupled Data Architecture**: Large data arrays (`cards.js` ~300KB and `quiz.js` ~830KB) are externalized from `index.html` into a `data/` subdirectory with corresponding JSON mirrors for external tooling.
4. **State Persistence**: User study progress, scores, theme preferences, and domain filters are stored in `window.localStorage` per device.
5. **Defensive Performance**: Minimal DOM reflows, efficient element reuse, and lightweight memory footprint suitable for low-end mobile devices.

## 4. State Management Architecture

The application manages two primary state machines: **Flashcard Study Mode** and **Endless Quiz Mode**.

### 4.1 Global Application State
```javascript
// Application mode switch: 'study' (Flashcards) or 'quiz' (Multiple Choice)
let appMode = 'study';

// Flashcard Deck State
let deck = [];        // Array of remaining active card indices/IDs
let done = [];        // Array of completed card indices/IDs
let flipped = false;  // Whether the current card's answer is revealed
let filter = { type: 'all' }; // Filter object: { type: 'all' } | { type: 'cluster', cluster: 'People' } | { type: 'domain', domain: 'Total Rewards' }

// Multi-session storage object map: filterKey -> { deck: string[], done: string[] }
let sessions = {};

// Jurisdiction filter toggle (hides U.S. Employment Law for international learners)
let hideUsLaw = true;
```

### 4.2 Endless Quiz State
```javascript
let quiz = {
  queue: [],          // Active remaining question items in randomized queue
  pool: [],           // Reference snapshot of all filtered questions
  index: 0,           // Number of questions served in the current session
  correct: 0,         // Cumulative tally of correct answers
  answered: 0,        // Cumulative tally of answered questions
  current: null,      // Reference to the active question object
  currentChoices: [], // Array mapping displayed index (0-3) to original option index
  selected: -1,       // Selected option index (-1 if unanswered)
  locked: false,      // Boolean flag locking choices after selection
  showVi: true,       // Vietnamese translation display toggle (default: true)
  filterType: 'all'   // Quiz bank filter: 'all' (307 questions) or 'sjt' (175 SJT items)
};
```

## 5. Key Algorithms & Implementation Patterns

### 5.1 Fisher-Yates Shuffle
Used to randomize flashcard decks and quiz question presentation:
```javascript
function shuffle(array) {
  let currentIndex = array.length, randomIndex;
  while (currentIndex !== 0) {
    randomIndex = Math.floor(Math.random() * currentIndex);
    currentIndex--;
    [array[currentIndex], array[randomIndex]] = [array[randomIndex], array[currentIndex]];
  }
  return array;
}
```

### 5.2 Runtime Option Shuffling (Preventing Positional Guessing)
To ensure users evaluate question logic rather than memorizing position (e.g. "answer is always B"), options are dynamically randomized when rendered:
```javascript
function prepareQuestionChoices(q) {
  // Indices [0, 1, 2, 3] mapped to option positions
  const indices = [0, 1, 2, 3];
  shuffle(indices);
  quiz.currentChoices = indices; // Stores mapping: displayed index -> original option index
}

function answerQuiz(displayedIndex) {
  if (quiz.locked || !quiz.current) return;
  quiz.locked = true;
  
  // Resolve original option index from display mapping
  const originalIndex = quiz.currentChoices[displayedIndex];
  quiz.selected = displayedIndex;
  quiz.answered += 1;
  
  if (originalIndex === quiz.current.answer) {
    quiz.correct += 1;
  }
  renderQuiz();
  scrollCardToBottom();
}
```

### 5.3 Endless Practice Queue
Prevents quiz termination when the question pool is exhausted, reshuffling and repeating seamlessly:
```javascript
function nextQuizQuestion() {
  quiz.selected = -1;
  quiz.locked = false;
  
  // Reshuffle pool into queue when empty
  if (quiz.queue.length === 0) {
    quiz.queue = shuffle(quiz.pool.slice());
  }
  
  quiz.current = quiz.queue.shift();
  quiz.index += 1;
  prepareQuestionChoices(quiz.current);
  renderQuiz();
  scrollCardToTop();
}
```

## 6. Local Storage Persistence Protocol

Data stored in `window.localStorage` ensures zero data loss on browser refresh:

| Storage Key | Type | Description |
|---|---|---|
| `shrm-flashcards-theme` | `'light'` \| `'dark'` | Visual theme preference (default: `'light'`) |
| `shrm-flashcards-progress-v1` | JSON String | Flashcard completed sets categorized by active filter key |
| `shrm-flashcards-hide-us-law` | `'1'` \| `'0'` | Flag hiding U.S. Employment Law domain (default: `'1'`) |

### Storage Serialization Guard
```javascript
function saveProgress() {
  try {
    const payload = {
      v: DATA_VERSION,
      filter: filter,
      sessions: sessions
    };
    localStorage.setItem(STORAGE_KEY, JSON.stringify(payload));
  } catch (e) {
    console.warn('Storage quota exceeded or disabled:', e);
  }
}
```

## 7. DOM & UI Rendering Rules
1. **Pure String Interpolation & `escapeHtml`**: Dynamic HTML strings must escape user-supplied or untrusted characters:
   ```javascript
   function escapeHtml(str) {
     if (!str) return '';
     return String(str)
       .replace(/&/g, '&amp;')
       .replace(/</g, '&lt;')
       .replace(/>/g, '&gt;')
       .replace(/"/g, '&quot;')
       .replace(/'/g, '&#039;');
   }
   ```
2. **Scroll Management**:
   - `scrollCardToTop()` is invoked when loading a new card/question.
   - `scrollCardToBottom()` is invoked when an answer is clicked to smoothly reveal the explanation box without jarring viewport jumps.
3. **Event Delegation & Accessibility**:
   - Buttons utilize semantic `<button type="button">`.
   - Disabled states (`disabled` attribute) are applied dynamically to lock choices once answered.
   - ARIA roles (`role="tab"`, `role="tablist"`, `aria-selected`) are maintained on tab controls.
