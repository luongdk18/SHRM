# Skill 06: Git Workflow & Static Web Deployment

## 1. Hosting Architecture: Zero-Build Static Deployment
The **SHRM Study Platform** is architected to deploy directly onto **GitHub Pages**, Cloudflare Pages, Netlify, or any static HTTP web server without a compilation step (`npm run build`, Webpack, Vite, etc.).

### Deployment Modes
1. **GitHub Pages (Root Branch)**:
   - Repository Settings $\to$ Pages $\to$ Source: `Deploy from a branch` $\to$ Branch: `main` / `root`.
   - The site deploys instantly from `index.html`.
2. **Local Desktop Execution**:
   - Double-clicking `index.html` loads locally in the browser (`file:///.../index.html`).
   - Uses relative path script tags (`<script src="data/cards.js">`), ensuring functional execution even without a local web server (e.g. `npx serve`).

---

## 2. Path Resolution & Browser Cache Control

### 2.1 Relative Asset Resolution
All script references, font links, and CSS variables maintain relative path resolution:
```html
<script src="data/cards.js"></script>
<script src="data/quiz.js"></script>
```
Do **not** use absolute paths with leading slashes (`/data/cards.js`), as this breaks deployments hosted under repository subpaths (e.g., `https://username.github.io/SHRM/`).

### 2.2 Independent Data Caching
By decoupling static UI (`index.html` ~60KB) from data assets (`data/cards.js` ~300KB and `data/quiz.js` ~830KB):
- The browser caches data payloads independently.
- UI tweaks, CSS updates, and bug fixes to `index.html` can be refreshed instantly without re-downloading unchanged quiz banks.

## 3. Pre-Commit Verification Checklist

Before staging and committing changes to `git`, execute the following automated validation protocol:

### Step 1: Syntax Validation
Verify that `index.html` and script files contain valid JavaScript syntax:
```bash
node -e "const fs = require('fs'); const html = fs.readFileSync('index.html', 'utf-8'); const script = html.split('<script>')[1].split('</script>')[0]; new Function(script); console.log('Syntax OK!');"
```

### Step 2: Data Mirror Integrity
Confirm that `data/cards.js` and `data/cards.json` match, and `data/quiz.js` and `data/quiz.json` match:
```bash
node -e "const q = require('./data/quiz.json'); console.log('Quiz count:', q.length);"
```

### Step 3: Git Status Review
Check working tree for untracked scratch files:
```bash
git status
```
Ensure temporary Python scratch scripts (`scratch/*.py`) or raw PDFs are either excluded via `.gitignore` or properly accounted for.

## 4. Git Commit & Release Conventions

### 4.1 Commit Message Conventions
Follow conventional commit prefixes:
- `feat:` New test questions, features, or UI capabilities.
- `fix:` Bug fixes, typo corrections, distractor balance adjustments.
- `perf:` Performance optimizations, asset splitting, layout rendering improvements.
- `docs:` Documentation, README updates, or skills additions.
- `refactor:` Code restructuring without changing user-facing behavior.

### 4.2 Standard Deployment Command
```bash
git add .
git commit -m "docs: add comprehensive engineering skills repository"
git push origin main
```
Following push, GitHub Pages automatically rebuilds and serves the updated application within 60–120 seconds.
